# 图解讲解

- 按“输入什么 → 做什么 → 输出什么 → 为什么需要”组织讲解。采用一个贯穿全文的具体例子；先给整体流程，再解释局部，不让读者在大量名词之间跳转。
- 技术过程从实际起点开始。例如训练说明覆盖数据与标签准备、前向输出、与标签比较得到 loss、求梯度、更新权重。显存、公式或实现细节服务于理解过程，不抢占主要篇幅。
- 说明张量形状和单位；公式后解释符号、计算对象、结果如何用于下一步。数字例子是示例就明确标注，不把简化假设说成真实模型配置。
- 按讲解对象选图，不强行用线性流程表示所有关系：
  - 顺序步骤：create_flow_diagram，每张 2–8 步。
  - 架构、分支、合并、跳连、反馈：create_architecture_diagram。节点 row/column 从 0 起，每格一节点；让主干沿行或列展开，分支放旁边。edges 用 id 引用节点，连接说明显示在图下编号图例。建议每图 3–8 节点，复杂架构拆为全局与局部图，文字解释跳连的作用。
  - 小矩阵或乘法：create_matrix_diagram。multiply 只传两个输入矩阵，工具计算并返回乘积；用 product 核对讲解，图中数值按 5 位有效数字显示。
  - 张量布局或维度变化：create_tensor_diagram，标注 B/N/D 等维度含义和每步操作。工具画示意，不验证形状；先核对 reshape 的元素数或矩阵乘法维度。
  - 实验数据、趋势或类别对比：create_data_chart。明确单位，系列长度与标签对应；同图只放可比单位。折线横轴为等距类别，不用它表示不等间距数值横轴的真实斜率。只用用户数据、已读来源或明确标为“示例”的数值。
- 多张图放在对应讲解段落附近，以图号和短图注串联整体与细节。维度、符号、配色含义保持一致；不要用一张拥挤大图替代局部解释。
- 将返回的 markdown 放在对应段落附近，并用正文解释图的重点。工具失败时可用文字箭头或表格继续说明，如实说明未生成图片。
- 先回应读者困惑，再展开必要细节。对已明确的结论直接表达，避免重复防御性措辞；未经核实的事实保留必要限定。
- 用户要保存图解文档时同时加载 learning-document，生成 MD 和 PDF 并归档；只问一个知识点时直接回答，不强制创建文件。
- 工具返回成功表示图片已生成，不等于模型已看图检查。当前不具备图片视觉回读工具，不声称逐图检查排版；遇到过多节点或长文应主动拆图。
